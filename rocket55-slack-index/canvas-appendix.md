The original Slack export only carried Canvas *titles and links*, not their bodies. Using live read-only access to the Slack workspace, I retrieved the contents of the highest-value Canvases. ## The standardized client "Overview" template

Nearly every active client has a pinned Canvas titled **`<Client> Overview`**, **`Channel Overview`**, **`Resources`**, or **`Important Links`** (see the inventory at the bottom — ~40 of them). They follow a **consistent skeleton**, which *is* the onboarding/account template:

```
# <Client> Overview
## 👥 Team            → CSM/AD, Web PM, SXO, RevOps, Social, Paid (named owners)
## 📅 Key Dates       → Internal Kickoff · Client Kickoff · Roadmap Meeting
## 📄 Client Assets   → brand guidelines, style guide, logos
## 🔑 Key links
   ADMIN     → Google Folder · Mission Control · Proposal · Internal Sales Handoff /
                Handoff Brief · Marketing Plan Blueprint · Discovery+Kickoff Agenda ·
                Kickoff Recording (Fathom) + Notes · Asset Tracker · (Signed MSA / SOW)
   GENERAL   → Reporting Dashboard (Looker) · Ongoing Agenda / Ongoing Notes (Notion)
   PAID      → Campaign Plan
   SXO       → Keyword Map · GBP Assessment · Technical SXO Assessment
   RevOps    → Technical Roadmap
   Social    → Social Media Framework + Calendar
   Web       → Web Project Brief · Timeline (TomsPlanner) · Questionnaire
## ✅ Access          → Ads · GA · LinkedIn · GTM · Search Console · Website (checkboxes)
## 📝 Client Notes
```

Two recurring, **templated artifacts** confirm this is a system, not ad-hoc:

- **"Mission Control"** — a per-client tracker spreadsheet. The *same tab* (`gid=1509272238`) appears across Atwell, Ispiri, Toppan Merrill, Maryland Oncology, and Turn Style, meaning it is a **master template cloned for each account**.
- **"Internal Sales Handoff" / "Internal Handoff Brief" / "Sales Brief"** — the sales→delivery handoff doc, present on Halco, Maryland Oncology, Work Smart IT, and others.

## Account-management process docs (industrial-manufacturing pod)

### Weekly Pod Meeting — runs on EOS/Traction
The `industrial-manufacturing-pod-4` **"Weekly Pod Meeting"** Canvas uses the classic EOS Level‑10 structure:
- **Scorecard / metrics review**
- **Issues list (IDS: Identify, Discuss, Solve)** — mid-week problems
- **At-risk / health flags** — clients trending red on budget, scope, satisfaction, or churn
- **New/updated strategy discussions** and **Growth / upsell opportunities**

Real entries (week of 7/20/26) show it working: per-client action items (Prinsco paid backup, Rayus→PM Jason, C2→PM Rachel/CSM Trey, MN Oncology off-boarding), staffing red/orange flags ("Aaron's coverage of Kiley accounts is an orange flag"), and live SOW status ("CPC relationship is extremely strained… SOW is shared, going to start work with the verbal agreement").

### Transition List — the account-handoff SOP
`"Transition List (who do I need to meet with)"` is a checklist for reassigning accounts when CSMs change. It names each incoming owner (Evan, Emma, Kiley, Zander, Nick), the outgoing owner to meet, and each client to transition — with checkboxes. This is the mechanism behind the "master account list" reassignments seen in `pm-am-resourcing`.

### Per-client Scorecard
`thern` has a **"Thern weekly scorecard"** — a metrics table (Web leads/wk, RFQs, CAD downloads, call leads organic/paid, AI-sourced leads) with **Goal / This week / Trailing‑4‑wk avg / Miss streak / Status (🟢🟡🔴)** and a plain-English notes section. A reusable client-health scorecard format.

### OOO Coverage Plan
`industrial-manufacturing-pod-4` **"Out of Office Coverage Plan"** template: per-person Dates offline / Availability / Coverage, plus a Project Coverage block (Status, Contacts, Resources). Paired with the workspace-wide **"Upcoming OOO"** Canvas (in `general` + `r55_out-of-office`) that Paige refreshes weekly from Accelo.

### Upcoming Clients & Work — new-business pipeline
`obviouslee-admin` **"Upcoming Clients & Work"** tracks pending/launching work with partner **OM Digital** and **Obviouslee**, keyed off a **"Brief of Partnership"** doc that "outlines what OM owns per client and what R55 is responsible for." Covers Bark, Streamsong, Sewing Down South, USC‑HRSM — including which channels R55 vs. the partner owns, and (for USC‑HRSM) the account being run in **Asana**.

## Emerging practice: Claude Projects as a per-project knowledge base

The `mmt-web` **"Latest Status Report"** Canvas contains a notable rollout note from the PM:

> "New item I'm rolling out across all projects. As soon as I become PM on a project, I set up a project-specific folder in Claude and turn it into a knowledge base. It's connected to my email, Slack, and Fathom, so… it can house all the project knowledge. It's been great for recapping items, drafting status updates, and finding things discussed in past meetings."

This is Rocket55 independently building the same kind of connected knowledge base this indexing exercise produces — worth knowing as you think about how to package these outputs.
